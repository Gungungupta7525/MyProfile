News Classifier with RAG

A news text classification system built with scikit-learn, where retrieval-augmented generation grounds each prediction in retrieved context instead of relying on what the model already 'knows'.

The context

Standard text classification is a solved-enough problem: vectorise the text, train a classifier, predict a label. It works well when the categories are stable and the vocabulary that signals them is predictable.

News doesn't work quite like that. The same event gets described in completely different language depending on the outlet and the day, and a word like "surge" is meaningful only in the context of what it's describing. A bag-of-words model sees the word; it doesn't see the event.

The problem

A classifier trained purely on text learns associations between surface words and labels. Two failure modes follow from that:

  • Vocabulary gaps. A story about a company reporting losses may never use the words in the training examples for that category. The features simply aren't there.
  • Out-of-distribution articles. A new event with unfamiliar phrasing has no signal the model can latch onto, so it falls back to whatever the prior distribution suggests.

The approach

Text preprocessing

The standard cleanup first — lowercasing, removing noise, and consistent tokenisation so that the same word produces the same feature whether it appears as "Markets" or "markets".

TF-IDF feature extraction

TF-IDF for the vectorised representation, which has a useful property here: a word that appears in every article carries almost no information, so it gets down-weighted automatically. That matters for news, where terms like "said", "report", and "according" are everywhere and signal nothing.

Retrieval-augmented generation

The RAG stage is the interesting part. Rather than asking the classifier to predict from the article text alone, the system retrieves relevant reference context and uses that alongside the article. The retrieval step supplies the background knowledge a bag-of-words model structurally cannot have — what the entity is, what the event is, how it relates to the categories.

RAG helps here for a specific reason: it adds information the model was never trained on, rather than re-arranging information it was.

The combined pipeline

Retrieval and classification run as one pipeline — retrieve context for the incoming article, then classify with both the raw text and the retrieved context in view. The goal is better accuracy on articles that sit close to, or outside, the edge of the training distribution.

Results

The pipeline improves accuracy on articles where retrieval supplies useful context, and doesn't help much where the article is already well-covered by the training vocabulary.

I want to be precise here: I evaluated the retrieval-augmented version against the TF-IDF baseline on the same splits, and the gain was real but concentrated in a subset of the data rather than uniform. Reporting a single averaged number would have hidden exactly the pattern that matters.

What I'd do differently

  • Ablate properly. I compared RAG-plus-TF-IDF against plain TF-IDF, but I should have measured the retrieval step in isolation. Without that, I can't say whether the improvement came from retrieval or from the extra context tokens changing how the classifier weights things.
  • Measure retrieval quality separately. Whether the retriever returns relevant context is its own problem, separate from whether the classifier uses it well. I treated them as one thing and couldn't tell which one was limiting.
  • Start with a stronger baseline. TF-IDF is a reasonable starting point, but I should have compared against a modern sentence embedding before investing in the retrieval layer. It's possible much of what RAG was doing for me, an embedding would have done more simply.
